## 5. 방법 · 함정 (새로 배운 것)

- **운영 스키마 차이**: `requests.updated_at` 없음 · `bids.selected` 없음 · `companies.phone` 없음 · `users` 직접 조회는 500. SQL 함수에서 이 칸을 쓰면 42703 → 앱엔 400. 선택 정보 원본은 `requests.selected_bid_id / selected_company_id`, 전화번호는 security definer 함수로 `users.phone`.
- **`bids.company_id` 에 업체 주인 사용자 ID 가 들어 있을 수 있다** — 업체 ID 가 필요하면 `resolveCompanyId`/`resolveRoomCompanyId`.
- 선택 직후 요청 상태는 `site_visiting`(041), 최종 견적 뒤 `final_quote_submitted`, 예약 확정 `escrow_pending`, 결제 뒤 `in_progress`, 정산 뒤 `completed`.
- 운영 DB 를 앱 밖에서 직접 읽고 쓰는 호출은 자동 권한 검사가 막는다 — 확인은 화면으로, 조회·수정은 SQL 파일로 대표에게.
- 대표 번호 하나에 세 역할 → 알림·말풍선이 섞여 보일 수 있다(실사용자는 아님).
- 5-1. 점검 데이터 정리: `docs/sql/cleanup-check-2026-09-24.sql`(점검 후기 숨김 · `[점검]` 채팅 삭제). 2차 거래 끝나면 다시 실행 + 잘못된 방(`9e8b3138…_9e8b3138…`)의 결제 기록 1건 삭제를 추가할 것. 요청·입찰·에스크로는 관리자 「테스트 데이터 정리」.
- 커밋 메시지는 파일로(BOM 없이). git 은 `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=safe.directory GIT_CONFIG_VALUE_0='*'`. 파이썬 편집은 `newline=''` 로 줄끝 유지.
- 같은 폴더에서 다른 창이 개발 서버를 돌릴 수 있다 — 브랜치 바꾸기 전에 `git status` 로 남의 변경이 없는지.
