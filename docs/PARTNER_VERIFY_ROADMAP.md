# 파트너 서류 자동검증 — 향후 할 일 (OCR · 국세청 API)

작성 2026-09-23 · 대표 확정: **「OCR·국세청 API는 향후 해야 할 일」**

## 0. 왜 이 문서가 생겼나

파트너 랜딩이 **「사업자등록증 업로드 · OCR + 국세청 API 자동 검증 · 무인」**, **「관리자 3초 승인」**을
내걸고 있었는데 저장소에 그 코드가 한 줄도 없었다(2026-09-23 검색 0건). 실제로는 파일이 storage 에
올라가고 **사람이 열어 보고 승인**한다. 그래서 랜딩 문구를 사실대로 내렸고(#690), **기능 자체는
여기 로드맵으로 옮긴다** — 문구를 지운 것이지 계획을 접은 것이 아니다.

## 1. 지금 실제 흐름 (기준선)

```
파트너 신청(PartnerLandingScreen STEP1~4)
  → 사업자등록증/보험증권/신분증 파일 업로드      … uploadFile("documents", …)
  → partner_leads 행 생성
  → 관리자(AdminScreen)가 열어 보고 승인/반려     … 사람 눈 100%
```

- 자동으로 대조하는 것: **없음**
- 사업자등록번호는 사용자가 **직접 입력**한 값(`form.bizNo`)이고, 업로드한 증명서와 대조하지 않는다.

## 2. 넣을 것 둘 (순서대로)

### ① 국세청 사업자등록 상태조회 — 먼저, 싸고 확실하다
- 공공데이터포털(data.go.kr) 「국세청_사업자등록정보 진위확인 및 상태조회 서비스」. **무료**.
- `상태조회`: 사업자번호 → 계속사업자 / 휴업 / 폐업 + 과세유형. **번호만으로 된다.**
- `진위확인`: 사업자번호 + 대표자명 + 개업일자가 모두 맞아야 통과. 신청 폼에 개업일자 칸이 없으니
  이 항목을 쓰려면 폼에 한 칸을 더 받아야 한다(그때 결정).
- 붙이는 자리: 신청 제출 시(또는 관리자 화면에서 버튼 하나)로 호출 → 결과를 `partner_leads` 에 적고
  관리자 화면에 **배지**로 보여 준다. 승인 자체는 여전히 사람이 누른다.
- ⚠️ 판정 문구를 부풀리지 말 것 — 「폐업 아님」까지가 사실이고 「검증된 업체」가 아니다.

### ② 사업자등록증 OCR — 그다음
- 후보: 네이버 CLOVA OCR(사업자등록증 전용 템플릿) · Upstage Document AI · Google Vision.
- 뽑을 값: 사업자등록번호 · 상호 · 대표자명 · 개업연월일.
- 쓰는 법: 사용자가 **입력한 값**과 증명서에서 **읽은 값**을 대조해 «일치/불일치» 배지만 만든다.
  불일치라고 자동 반려하지 않는다(사진이 흐리면 사람이 봐야 한다).
- ⚠️ 유료다. 건당 단가와 월 상한을 먼저 정하고 붙인다.

## 3. 제약 (착수 전 확인)

- **Vercel 함수 개수**: `api/` 에 지금 13개(테스트 파일 1개 포함 · Hobby 한도 12). 새 엔드포인트를
  추가하면 배포가 막힐 수 있다 → 기존 `api/admin/users.js` 같은 곳에 action 하나로 얹거나,
  `vercel.json` rewrite 로 합친다(`/api/cron/autonomous-cycle` 이 이미 그 방식).
- **키 보관**: 서비스키는 서버 환경변수로만. 클라이언트에서 국세청 API를 직접 부르지 않는다
  (키가 노출되고, CORS 도 막힌다).
- **개인정보**: 지금 `uploadFile` 이 `getPublicUrl` 을 쓴다 → 사업자등록증·신분증이 **공개 URL**이다.
  OCR 을 붙이기 전에 **비공개 버킷 + 서명 URL**로 바꾸는 편이 낫다(별도 작업 · 관리자 검수 화면도 같이 손봐야 한다).

## 4. 붙인 뒤에 되돌릴 문구

기능이 실제로 돌기 시작하면 아래를 다시 사실대로 올린다(그 전에는 올리지 않는다).

| 지금(사실) | 기능이 생기면 |
|---|---|
| 담당자가 서류를 직접 확인 | 사업자등록 상태 자동 조회 + 담당자 확인 |
| 승인 · 확인이 끝나면 바로 알려 드립니다 | (실측 SLA가 생기면 그 숫자로) |
