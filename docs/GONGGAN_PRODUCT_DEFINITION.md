# 공간사이 제품 정의 및 설계안 (비-Prubi)

> 목적: 공간사이 3개 제품(공간마켓·공간라운지·공간매거진)을 **설계를 시작할 수 있을 만큼** 정의한다.
> 이 문서는 **문서 산출물**이며, 여기서 코드를 작성하지 않는다. Prubi(prubi.online)는 이 문서의 대상이 아니며 별도 운영·분리 유지한다.
>
> 상태: **초안 (사용자 승인 대기)** · 작성일 2026-08-07
> 근거: `hook44445-ops/gonggan-market` 저장소 코드 직접 조사(라우팅·DB 스키마·lib·screens 확인).

## 0. 조사 결과 — 저장소의 실제 구조 (반드시 읽을 것)

지시서의 전제("공간 3종은 미정의, Prubi만 운영 중")와 저장소 실제 상태는 크게 다르다. 코드를 직접 파악한 결과, **3개 제품은 독립된 3개 앱이 아니다.**

### 0-1. 한 문장 요약
**공간마켓과 공간라운지는 하나의 앱·하나의 Supabase DB 안에 함께 구현돼 있고, 공간매거진은 별도 제품이 아니라 "라운지 글을 매거진 레이아웃으로 재구성한 뷰 + 외부 블로그(네이버 JAFA1) SEO 신디케이션"이다.**

### 0-2. 근거 (코드에서 확인)
- **단일 SPA·단일 앱**: `src/App.jsx` → `src/components/MainApp.jsx`(5,725줄) 하나가 마켓과 라운지 화면을 `screen` 상태로 전환한다. **react-router 미사용**(수동 `pathname` 분기, Vercel catch-all rewrite).
- **단일 인증**: 전화번호 OTP + `localStorage`(`gonggan_user`) 세션. `supabase.auth`와 **독립**. → 이미 하나의 계정 체계.
- **단일 DB(약 32개 테이블)**:
  - 마켓 도메인: `users, companies, bids, requests, reviews, portfolios, chats, escrow_payments, escrow_payouts, payment_orders, payment_transactions, fee_config, change_orders, contract_notes, contract_scopes, customer_reports, company_documents, phase_photos, request_reposts`
  - 라운지 도메인: `lounge_posts, lounge_comments, lounge_post_likes, lounge_comment_likes, lounge_saves, lounge_blocks, lounge_reports, lounge_chat_requests, lounge_categories, lounge_seed_posts`
  - 공용/운영: `notifications, activity_logs, admin_logs, ops_config, webhook_logs`
- **매거진은 테이블이 없다**: `article`/`magazine`/`blog_post` 테이블 **부재**. `src/lib/magazine.js`는 순수 함수로 `lounge_posts`를 매거진 섹션(오늘의 Space·Editor's Pick·Deep Article 등)으로 조립할 뿐(저장·마이그레이션 없음). `src/lib/blogPublisher.js`는 라운지 글을 네이버 블로그(JAFA1)로 신디케이션해 검색 유입→라운지 선순환을 노린다.
- **AI 콘텐츠 공장**: 마이그레이션 `094_lounge_ai_content_factory.sql` 등 — AI가 생성하는 것도 결국 `lounge_posts`다.

### 0-3. 기타 사실
| 항목 | 실제 상태 |
|---|---|
| 배포 | production 운영 중(`gonggan-market-qkdh.vercel.app`), PR #654까지 머지, 마이그레이션 124개 |
| 언어 | `src` 329개 파일 전부 **JS/JSX** (TypeScript 0개) — 지시서 "React+TS" 전제와 불일치 |
| Vercel 함수 | **12/12 만석**(Hobby 상한). 신규 함수 = 기존 통합/삭제 필수 |
| `src/lib/seo.ts` | 이 저장소에 없음(Prubi 파일 — 이식 대상). 이식 시 `seo.js`로 |
| 통신판매업 신고 | 이미 존재: **2026-성남중원-0463** |
| AI Executive Office | LLM 4인 검수 보드 등 방대한 콘텐츠 자동화가 이미 배포됨(핵심 거래와 무관) |

### 0-4. 함의 (설계 전체를 좌우)
1. **"3개 제품 = 3개 DB 분리"는 현재 코드와 정면 배치된다.** 마켓·라운지는 이미 한 DB·한 계정. 매거진은 DB가 없다. 지금 억지로 3분할하면 대규모 마이그레이션 + 회귀 위험.
2. **계정 공유(단일 계정)는 이미 달성돼 있다.** 별도 작업 불필요 — 단, 서브도메인으로 쪼개면 오히려 깨진다(0-5).
3. **매거진은 "만들 제품"이 아니라 "라운지 위에 얹는 SEO 레이어"다.** 이 인식이 도메인 구조를 바꾼다(§3).

### 0-5. ⚠ 서브도메인 분리 시 인증이 깨지는 문제 (중요)
현재 세션은 `localStorage`(`gonggan_user`)에 저장된다. `localStorage`는 **origin(서브도메인 포함)별로 격리**된다. 따라서 마켓·라운지를 `market.gonggansai.com` / `lounge.gonggansai.com`으로 쪼개면 **단일 계정 공유(확정 요구사항)가 자동으로 깨진다.** 유지하려면 (a) 부모 도메인 `.gonggansai.com` 쿠키 기반 세션으로 전환하거나, (b) 앱을 **같은 origin(서브디렉터리)** 에 두어야 한다. 이 제약이 §3 권고를 이전 초안과 다르게 만든다.

## 1. 확정된 사실 (사용자 확인 완료)

- **공간마켓** = 인테리어·집수리 업체 **중개(매칭)**. 대상 = "인테리어와 집수리 가능한 일체".
- **수익 모델** = **거래 성사 수수료** (→ 대금이 플랫폼을 경유해야 수취 가능. 에스크로/`confirm-payment`/`fee_config` 코드와 정합).
- **공간라운지** = **온라인 인테리어·라이프 커뮤니티** (무료).
- **공간매거진** = **AI 생성 중심 + SEO 유입** (→ 코드상 이미 "라운지 글의 매거진 뷰 + 외부 블로그 신디케이션"으로 구현됨).
- **계정** = 3개 제품 **단일 계정 공유** (코드상 이미 단일 계정).
- **도메인** = **gonggansai.com 보유**, **Prubi(prubi.online) 분리** 유지.
- **산출물 용도** = 공간사이 **홈페이지 설계안**으로 활용.

### ⚠ 아직 확인이 필요한 항목 (임의로 채우지 않음)
- 각 제품 **성공 지표 수치 목표** (아래는 *제안*).
- **공간마켓 목표 출시 시점** (로드맵 날짜는 임의로 채우지 않음).
- **수수료율·정산 방식** (자동송금/자동환불 금지 원칙 유지).

## 2. 산출물 ① — 제품 정의서 (제품별 1페이지)

> "성공 지표" 숫자는 **제안(확인 필요)** 이다. 방향만 확정.

### 2-1. 공간마켓
- **한 문장 정의**: 인테리어·집수리가 필요한 **소비자**가 검증된 **시공 업체**를 찾아 견적받고 안전결제로 계약하러 오는 곳.
- **사용자**: (수요) 일반 소비자 · (공급) 인테리어·집수리 업체.
- **돈 내는 사람**: **공급자(업체)** — **거래 성사 수수료**(플랫폼 경유 결제 시 수취).
- **성공 지표(제안)**: 1차 = **성사된 거래 건수**. 보조 = 견적 요청 수·업체 응답률·재이용률.
- **안 하는 것**: 부동산 임대·매매 중개(공인중개사법 회피) / 자동 송금·환불 / 플랫폼의 직접 시공·하자 책임(중개자 고지로 명확화).

### 2-2. 공간라운지
- **한 문장 정의**: 인테리어·집꾸미기·일상(라이프) 이야기를 사진·후기·Q&A로 나누는 **무료 온라인 커뮤니티**.
- **사용자**: 인테리어 관심 사용자 + 마켓 이용 전/후 고객.
- **돈 내는 사람**: **없음**(무료). 간접 가치 = 마켓 유입·신뢰·SEO 콘텐츠 축적.
- **성공 지표(제안)**: 1차 = **주간 활성 작성자/글 수**. 보조 = 방문자·마켓 전환.
- **안 하는 것**: 유료 멤버십 / 오프라인 모임 운영(지금은 온라인만) / 별도 DM 인프라 신설(마켓 채팅 재사용).

### 2-3. 공간매거진
- **한 문장 정의**: 라운지에 쌓인 콘텐츠를 **매거진 레이아웃 + 외부 블로그 신디케이션**으로 노출해 **검색 유입**을 만드는 SEO 레이어.
- **사용자**: 검색으로 유입되는 잠재 고객(아직 마켓/라운지를 모르는 사람).
- **돈 내는 사람**: **없음**. 목적 = **SEO 유입** → 마켓·라운지 연결.
- **성공 지표(제안)**: 1차 = **오가닉 유입 세션 / 색인 페이지 수**. 보조 = 유입→마켓 전환.
- **안 하는 것**: 별도 콘텐츠 DB 신설(라운지 재사용) / 사람 전담 편집팀 / 얇은 콘텐츠 대량 양산("기본 noindex + 명시적 index" 적용).

## 3. 산출물 ② — 브랜드·도메인 구조안

### 3-1. 권고 배치 (코드 실제 구조 + 단일 계정 요구 반영)
> ⚠ 이전 초안은 마켓·라운지를 서브도메인으로 권했으나, 조사 결과 **단일 계정이 `localStorage` 세션**이라 서브도메인 분리 시 로그인 공유가 깨진다(§0-5). 따라서 **같은 origin(서브디렉터리) 우선**으로 수정한다.

| 서비스 | 위치 | 형태 | 근거 |
|---|---|---|---|
| 공간사이 허브 | `gonggansai.com` | 루트 | 3개 제품 소개 홈(설계안 용도) |
| 공간마켓(앱) | `gonggansai.com/` 또는 `/app` | **같은 origin** | 현 SPA·단일 계정(`localStorage`) 유지. 분리 시 인증 재설계 필요 |
| 공간라운지 | `gonggansai.com/lounge` | **서브디렉터리** | 이미 `/lounge/...` 딥링크가 코드에 구현됨. 계정·DB 공유 그대로 |
| 공간매거진 | `gonggansai.com/magazine` | **서브디렉터리** | 라운지 글의 매거진 뷰 → 루트 도메인 SEO 권위 상속 |
| Prubi | `prubi.online` | **분리 유지** | 대상 다름 + SEO 자산 축적됨. `.online`이라 계정 공유서 자연 제외 |

### 3-2. SEO·기술 근거 (서브디렉터리 우선)
- **매거진 = 서브디렉터리**: 목적이 검색 유입뿐이므로 루트 도메인 권위를 **상속**하는 서브디렉터리가 유리. 신생 도메인에서 콘텐츠 권위를 한 곳에 집중.
- **라운지·마켓 = 같은 origin**: (1) 단일 계정이 `localStorage` 세션이라 same-origin이라야 자동 공유(§0-5). (2) `/lounge/...` 딥링크가 이미 구현됨. (3) 서브도메인으로 쪼개려면 부모 도메인 쿠키 세션으로 **인증을 재설계**해야 하고 회귀 위험이 크다 — 1인 개발 원칙(과설계 금지)에 반함.
- **서브도메인이 정당해지는 때**: 훗날 라운지/매거진 트래픽이 커져 **독립 배포·독립 12함수 예산**이 절실해지면 그때 부모-쿠키 세션으로 전환하며 분리. 지금은 이르다.

### 3-3. 이관 시 조치
- Prubi `index.html`의 Organization JSON-LD `url`(`prubi.online`)은 Prubi 것이므로 **그대로 둔다**. 공간사이 JSON-LD를 `gonggansai.com` 기준으로 **새로 작성**.
- Prubi의 `src/lib/seo.ts` "**기본 noindex + 명시적 index**" 패턴을 공간사이에 이식(현 저장소는 JS → `seo.js`). 매거진·라운지 공개 글만 명시적 index, 나머지 noindex.

## 4. 산출물 ③ — 공간마켓 MVP 범위

> 이미 배포된 앱이 있으므로 MVP는 "새로 만들 것"이 아니라 **"출시에 꼭 필요한 것 vs 지금 없어도 되는 것"의 선별**이다.

### 4-1. 출시에 **반드시 필요한 것** (짧게)
1. 업체 등록/온보딩(무인 입점 위저드 — 존재).
2. 시공 사례·업체 노출 + 지역 매칭(고객 활동지역 ∩ 업체 영업지역).
3. 고객 요청 → 견적(bids) → 채팅.
4. 리뷰(성사 후 신뢰).
5. 결제 경유 + 수수료 수취 최소 흐름(`escrow`/`confirm-payment`/`fee_config`) — 자동송금·환불 금지 유지.
6. 법적 고지: 통신판매중개자 지위 고지, 신고번호(2026-성남중원-0463), 개인정보처리방침.
7. 로그인/단일 계정(현행 유지).

### 4-2. **없어도 되는 것** (길게 — 출시 후로 미루거나 제거)
출시에 직접 기여하지 않으면서 1인 개발·12함수 상한을 갉아먹는 것들. 지시서 5항(과설계 금지)과 직결.

- **AI Executive Office / LLM 4인 검수 보드 / 품의·결재 타임라인**(`executiveOffice.js`, `aiEditorialBoardLLM.js`, `CeoOffice.jsx`, `ChiefSecretaryBoard.jsx` 등) — 인상적이나 거래 성사와 무관. **출시 범위 밖.** LLM 호출·복잡도 유지비 큼.
- **매거진 자동 발행/신디케이션 OS**(`autoPublish*.js`, `publishing*.js`, `blogPublisher.js`, `fusion*.js`, `editorial*.js`, `humanizationEngine.js`) — 매거진은 SEO 레이어. 마켓 출시엔 불필요. 관련 함수(`api/trend/check-trends.js`)를 마켓에서 빼면 12함수 여유 확보.
- **트렌드 발견·수집 파이프라인**(`trendCollector/trendDiscovery/timeTrend`) — 매거진 전용.
- **푸시 알림 dispatch/enqueue**(`api/push/*`) — 초기엔 문자(solapi)/이메일로 충분. 함수 2개 절약.
- **토큰 스토어 / TokenHistory**(`useSpaceToken`, `TokenStoreScreen`) — 수익이 "거래 수수료"로 확정됐으므로 토큰 경제는 **출시 범위 밖**.
- **라운지 스토리·AI 콘텐츠 공장** — 라운지/매거진 축. 마켓 출시 임계경로 아님.
- **prerender**(`api/prerender.js`) — SEO는 매거진(서브디렉터리)에서 담당. 마켓 앱은 로그인 후 기능이 본체.
- **관리자 seed-posts 등 데모/시드**(`api/admin/seed-posts.js`) — 실데이터 전환 후 제거(Mock/실제 구분 원칙).

> **정리 원칙**: 마켓 출시의 임계경로는 "업체·요청·견적·안전결제·리뷰·지역매칭·고지"뿐이다. 위 콘텐츠 자동화 스택은 **끄거나 마켓 배포에서 분리**하면 12함수 압박과 1인 유지보수 부담을 동시에 줄인다.

## 5. 산출물 ④ — 법적 확인 목록

> 법률 자문이 아니라 **확인해야 할 체크리스트**. 실제 판단은 전문가 확인 필요.

### 5-1. 중개업 해당 여부
