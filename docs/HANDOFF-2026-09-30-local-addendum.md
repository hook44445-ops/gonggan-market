## 1. ★오늘 먼저 — 아이폰 앱 실기기 확인 (182 뒤)

아이폰 앱(WKWebView)이 `localStorage` 를 앱을 껐다 켜도 지키는지가 핵심이다. 못 지키면 아이폰 사용자는 쓰기마다 «다시 로그인» 이 뜬다.

순서(테스트 계정 · 실제 고객 데이터 건드리지 않기):
1. 아이폰 앱 → 인증번호로 로그인
2. **앱을 완전히 끄고 다시 켠다** → 마이 › 알림함이 보이는지(보이면 토큰 유지)
3. 고객: 견적 요청 1건(테스트 문구) · 라운지 글·댓글·좋아요
4. 업체 계정: 그 요청에 입찰 → 입찰 수정
5. 마이 › 푸시 알림 설정 켜고 끄기

막히면:
- 화면 문구 그대로 + 맥 사파리 «개발자 › (아이폰) › 웹 속성» 콘솔 오류를 `docs/QA-2026-09-30-ios.md` 에 적는다(토큰·전화번호·인증번호는 가린다)
- 토큰이 재시작마다 사라지면 gonggan-ios 쪽을 고친다: WebView 가 기본(영구) 데이터 저장소를 쓰는지(`incognito`/비영구 설정 없음) · 앱 시작 때 저장소를 지우는 코드가 없는지
- 웹 코드(이 저장소 `src/`)는 고치지 말고 기록만 → 클라우드 세션이 고친다

## 2. 아이폰 푸시(오전 2-1 그대로 · 1순위) + 누르면 여는 주소

오전 규격 그대로(`gonggan:push-token` · `gonggan:push-ask`). 여기에 **알림을 눌렀을 때**를 더한다:
- 발송기는 `data: { url }` 로 보낸다. 앱은 탭 이벤트(`addNotificationResponseReceivedListener` · 꺼진 상태는 `getLastNotificationResponseAsync`)에서 `url` 을 WebView 에 연다.
- `url` 은 `/` 로 시작하는 **우리 사이트 경로만** 받는다(다른 도메인이면 무시). 예:
  - `/?open=review-card` — 업체 마이의 후기 카드(181)
  - `/?open=invite` — 친구 초대 화면
  - `/p/<업체>` — 찜한 업체 새 사례(179)
  - `/lounge/posts/<id>` — 라운지 인기 글(174)
  - `/` — 그 밖
- 앱이 이미 떠 있어도 **주소를 새로 불러야** 한다(웹 `App.jsx` 가 처음 열릴 때 `?open=` 을 읽는다) — `webview.injectJavaScript("location.href = '<url>'")` 또는 `source` 교체.
- 규격이 정해지면 `docs/PLAN-2026-09-30-no1-download-revisit.md` 4절에 «확정» 으로 적고 대표에게 알린다 → 클라우드가 웹 수신·Expo 발송을 붙인다.
